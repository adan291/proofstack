Guía · Proofstack v0.7

Tu portfolio y tu CV, desde un solo fichero

Escribes tu carrera una vez en profile.yaml. Proofstack genera la web, el CV en PDF y Word, y borradores de contenido. Todo lo que publica se puede comprobar, y nada se inventa.

  • Empezar
  • Código en GitHub
  • Ver un ejemplo real

Qué hace

Web de portfolio

Tu carrera como un mapa de áreas. Cada área enlaza a proyectos (problema, solución, aprendizajes) y a evidencias (contexto, acción, resultado). Se publica sola en GitHub Pages.

CV en PDF y Word

Una o dos páginas, una columna, apto para filtros ATS. Con --job lo ordenas para una oferta y te dice qué pide que tu perfil no menciona.

Editor en el navegador

proofstack studio abre formularios con los avisos junto a cada campo y una vista previa. Nunca guarda un perfil inválido.

Importadores

Trae tu experiencia, formación, skills, idiomas y certificaciones de LinkedIn, y tus repos públicos de GitHub. Nunca importa email ni teléfono.

Tres reglas que no se saltan

  1. Nada inventado. El CV y la web solo dicen lo que pone tu perfil. Si un modelo de IA añade un número que no está en tu perfil, sale marcado como aviso.
  2. Nada a medias. Cualquier TODO o enlace de ejemplo bloquea la publicación (proofstack doctor).
  3. Tu fichero manda. Es texto versionado en Git. Los importadores escriben siempre en un fichero nuevo y nunca sobrescriben el tuyo.

Desde cero, paso a paso

Necesitas JDK 25 (Temurin) y una cuenta de GitHub. No hace falta saber Java.

  1. Crea tu copia del repositorio

    En GitHub, abre el repositorio de Proofstack y pulsa Use this template → Create a new repository. Después clónalo en tu equipo.

  2. Consigue la herramienta

    Descarga proofstack.jar de la última Release y déjalo en la carpeta del repositorio. Crea un atajo para no escribir java -jar cada vez:

    # Windows (PowerShell)
function proofstack { java -jar proofstack.jar @args }

# macOS / Linux
alias proofstack="java -jar proofstack.jar"

    El atajo solo existe en la terminal donde lo creas. Ejecuta los comandos desde la carpeta del repositorio.

  3. Crea tu perfil

    Elige cómo empezar:

    # Desde cero
proofstack init profiles/tu-nombre --name "Tu Nombre" --headline "Backend Engineer" --language es

# O desde tu LinkedIn: Ajustes → Privacidad de datos → Obtener una copia de tus datos
proofstack import linkedin Basic_LinkedInDataExport.zip --out profiles/tu-nombre/profile.yaml

# Y añade tus repos públicos
proofstack import github tu-usuario -p profiles/tu-nombre/profile.yaml -o profiles/tu-nombre/profile.github.yaml

  4. Rellénalo en el navegador

    proofstack studio profiles/tu-nombre/profile.yaml

    Se abre un editor con una sección por bloque: persona, experiencia, proyectos, evidencias, idiomas… El panel Antes de publicar te lleva a cada campo que falta. Ctrl+S guarda.

    Un buen proyecto
    Dice qué problema había y cómo lo resolviste, y enlaza al código o a una demo.
    Una buena evidencia
    Contexto, lo que hiciste tú y el resultado. Sin cifra, mejor una frase honesta que un número inventado.

  5. Comprueba que está listo

    proofstack doctor profiles/tu-nombre/profile.yaml
proofstack build  profiles/tu-nombre/profile.yaml --out dist --with-cv

    Abre dist/index.html. doctor separa los errores, que impiden publicar, de los avisos, que son sugerencias.

  6. Publica en GitHub Pages

    1. Settings → Pages: en Source elige GitHub Actions.
    2. Settings → Secrets and variables → Actions → Variables: en Repository variables crea PROOFSTACK_PROFILE con el valor profiles/tu-nombre/profile.yaml.
    3. Haz git push a main, o lanza Actions → Deploy portfolio → Run workflow.

    La variable tiene que ser de repositorio. Si la creas dentro de un environment, el despliegue no la ve.

    Tu web queda en https://<usuario>.github.io/<repo>/, con un botón Descargar CV que baja el PDF.

Si algo falla

proofstack no se reconoce
El atajo no existe en esta terminal. Vuelve a crearlo (paso 2).
File not found: profiles/…
Estás en otra carpeta. Entra en la del repositorio con cd.
El despliegue falla en Ready to publish?
doctor encontró errores, o la variable PROOFSTACK_PROFILE falta o no es de repositorio. El log muestra las líneas ERROR.
La web da 404
El primer despliegue aún no ha terminado, o Pages → Source no está en GitHub Actions.
LinkedIn responde 401
La app de LinkedIn debe usar la página Member Data Portability (Member-Only Default Company Page), y la API solo sirve a cuentas del EEE o Suiza. Fuera de ahí, usa el ZIP.

Cómo está hecho

Java 25 con arquitectura hexagonal: un núcleo sin frameworks y un adaptador por cada entrada (YAML, LinkedIn, GitHub, Studio) y cada salida (web, CV, LLM). ArchUnit comprueba esas reglas en cada build. Cada fase empezó como una spec y cada decisión importante está en un ADR del repositorio.
