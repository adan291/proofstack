Tu portfolio y tu CV, desde un solo fichero

Proofstack trae tus datos de LinkedIn y GitHub a un fichero, profile.yaml, te deja completarlo en un editor en el navegador y genera con él tu web de portfolio y tu CV en PDF y Word. Cada git push los publica, y cada semana te propone tus repositorios nuevos. Esta guía explica qué hace y cómo usar cada pieza sin ayuda.

Arranque rápido

Con Java 25 y Git instalados (cómo), son cuatro pasos:

# 1. Tu copia: "Use this template" en GitHub, y clónala
git clone https://github.com/<usuario>/<repo>.git
cd <repo>

# 2. Perfil, GitHub, LinkedIn y editor, de una vez
./proofstack setup

# 3. La web y el CV en tu equipo
./proofstack build profiles/<tu-nombre>/profile.yaml --out dist --with-cv

# 4. Publicar (antes, los tres ajustes de «Publicar en GitHub Pages»)
git add -A
git commit -m "Mi perfil"
git push

Cada paso está explicado más abajo. Si es tu primera vez, sigue la guía en orden.

Qué es

Un portfolio de backend suele ser una lista de tecnologías que nadie puede comprobar. Proofstack organiza tu carrera en áreas (Backend, Arquitectura, IA, Liderazgo…) y cada área enlaza a dos tipos de prueba:

Proyectos

Qué problema había, cómo lo resolviste, qué aprendiste y dónde se puede ver: repositorio o demo.

Evidencias

Contexto, lo que hiciste tú y el resultado. Una frase honesta vale más que una cifra inventada.

Qué obtienes con ese fichero

Web de portfolio

Tus proyectos destacados nada más entrar, tu carrera como un mapa de áreas y la línea de tiempo. Estática, accesible y con efectos que se apagan si el visitante pide menos movimiento.

CV en PDF y Word

Dos páginas como mucho, en una columna, apto para filtros ATS. Se adapta a una oferta o a un área, y el teléfono solo va en la copia que envías.

Editor en el navegador

Studio: formularios con los avisos junto a cada campo, vista previa y botones para traer LinkedIn y GitHub. Nunca guarda un perfil inválido.

Importadores

Experiencia, formación, skills, idiomas y certificaciones desde LinkedIn, y repos públicos desde GitHub. Nunca traen email ni teléfono, y nunca tocan tus proyectos ni tus evidencias.

Un comando para empezar

setup crea el perfil, trae GitHub y LinkedIn, te dice qué falta y abre el editor. Puedes repetirlo cuando quieras.

Se mantiene solo

Cada git push publica. Cada lunes llega un pull request con tus repos nuevos, y cada tres meses una issue para traer LinkedIn.

Cómo funciona

Todo sale de un único fichero de texto versionado en Git. Las entradas lo crean o lo editan; las salidas lo convierten en lo que publicas.

  1. Nada inventado. El CV y la web solo dicen lo que pone tu perfil. Si un modelo de IA añade un número que no está en tu perfil, sale marcado como aviso.
  2. Nada a medias. Cualquier TODO o enlace de ejemplo bloquea la publicación.
  3. Tu fichero manda. Lo importado nunca pisa tus proyectos ni tus evidencias. Studio no guarda nada hasta que pulses Guardar, y la sincronización semanal te lo propone en un pull request.
  4. Tus datos privados, privados. El email solo aparece si lo escribes tú, y el teléfono nunca se publica. Las claves de LinkedIn se guardan en tu carpeta de usuario, nunca en el repositorio.

Por dentro: Java 25 con arquitectura hexagonal. Un núcleo sin frameworks y un adaptador por cada entrada y cada salida; ArchUnit comprueba esas reglas en cada build. Las decisiones están en docs/adr.

Instalar (una sola vez)

  1. Instala Java y Git

    JDK 25 (Temurin) y Git. Para compilar desde el código, también Maven 3.9. Comprueba que están:

    java -version      # debe decir 25
git --version
mvn -version       # solo si vas a compilar

  2. Ten el repositorio en tu equipo

    Si es tu primera vez, pulsa Use this template en GitHub para crear tu copia. Después:

    git clone https://github.com/<usuario>/<repo>.git
cd <repo>

  3. Prueba el lanzador

    El repositorio trae un lanzador, proofstack, que funciona igual en PowerShell, macOS y Linux. No hay que instalar nada más:

    ./proofstack --version

    La primera vez compila la herramienta con Maven, y tarda un par de minutos. Sin Maven, descarga proofstack.jar de la última Release y déjalo en la carpeta del repositorio.

    Ejecuta siempre desde la carpeta del repositorio. Las rutas como profiles/… son relativas a ella.

Tu perfil

  1. Créalo con un solo comando

    ./proofstack setup

    Te pregunta tu nombre y tu usuario de GitHub, y hace el resto:

    1. Crea profiles/tu-nombre/profile.yaml, o usa el que ya tengas.
    2. Trae tus repositorios públicos de GitHub y te deja elegir cuáles van al portfolio. Los que descartes se apuntan en github-ignore.txt y no vuelven a salir.
    3. Configura LinkedIn la primera vez: te dice cómo crear tu app (5 minutos, solo una vez) y guarda sus claves en tu carpeta de usuario, nunca en el repositorio. Después abre LinkedIn para que pulses Permitir e importa tu trayectoria.
    4. Te dice qué falta y abre Studio.

    Puedes repetirlo cuando quieras: tus proyectos y evidencias nunca se tocan, y si no hay nada nuevo el fichero queda igual. Si tu LinkedIn no está en el EEE o Suiza, usa el ZIP: ./proofstack setup --linkedin-zip Basic_LinkedInDataExport.zip.

    Ejemplo real: profiles/adan/profile.yaml.

  2. Rellénalo con Studio

    ./proofstack studio profiles/tu-nombre/profile.yaml

    Se abre el navegador con una sección por bloque: persona, experiencia, proyectos, evidencias, idiomas… El panel Antes de publicar te lleva a cada campo que falta, y a la derecha ves cómo quedan el CV y la web.

    Arriba tienes Traer de LinkedIn y Traer repos de GitHub. Traen lo nuevo a lo que estás editando y te enseñan qué ha entrado. No se guarda nada hasta que pulses Guardar.

    Guardar
    Ctrl+S o el botón Guardar. Si algo es inválido, no se guarda y se marca en rojo.
    Cerrar
    Ctrl+C en la terminal.
    Deshacer
    El primer guardado de cada sesión deja el fichero tal como estaba en profile.yaml.bak, y con Git puedes volver a cualquier versión.

    Si prefieres el YAML, ábrelo en VS Code o Kiro con la extensión de YAML: tendrás autocompletado gracias a la primera línea del fichero.

  3. Comprueba que está listo

    ./proofstack doctor profiles/tu-nombre/profile.yaml

    Separa los errores, que impiden publicar (un TODO, un enlace de ejemplo), de los avisos, que son sugerencias (un proyecto sin enlace).

La web y el CV en tu equipo

Un solo comando genera las dos cosas en la carpeta dist: la web de portfolio y, dentro de dist/cv, el CV.

./proofstack build profiles/tu-nombre/profile.yaml --out dist --with-cv

Abrirlos en Windows (PowerShell)

Start-Process dist\index.html    # la web
Start-Process dist\cv\cv.html    # el CV
Start-Process dist\cv\cv.docx    # el CV en Word

Abrirlos en macOS (en Linux, xdg-open)

open dist/index.html dist/cv/cv.html dist/cv/cv.docx
Qué genera build --with-cv
FicheroPara qué
dist/index.htmlTu web. El botón Descargar CV abre el CV.
dist/cv/cv.htmlEl CV para leerlo o imprimirlo: Ctrl+P → Guardar como PDF.
dist/cv/cv.docxEl CV en Word, para quien te lo pida en ese formato.
dist/cv/cv.mdEl CV en texto, para pegarlo en un formulario de candidatura.

dist/ no se sube a Git: se regenera cuando quieras. En local el botón abre cv.html; el PDF lo genera el despliegue automático.

Publicar en GitHub Pages

La primera vez, tres ajustes en tu repositorio. Después, cada git push publica solo y tu perfil se mantiene al día.

  1. Activa Pages

    Settings → Pages, y en Source elige GitHub Actions.

  2. Dile qué perfil publicar

    Settings → Secrets and variables → Actions, pestaña Variables. En Repository variables crea PROOFSTACK_PROFILE con el valor profiles/tu-nombre/profile.yaml.

    Tiene que ser una variable de repositorio. Si la creas dentro de un environment, el despliegue no la ve.

  3. Sube los cambios

    git add -A
git commit -m "Actualizo mi perfil"
git push

    En la pestaña Actions verás Deploy portfolio: pasa doctor, construye la web y el CV, genera el PDF y publica en unos 3 minutos. Tu web queda en https://<usuario>.github.io/<repo>/, y esta guía en /guide/.

  4. Deja que se mantenga solo

    Settings → Actions → General → Workflow permissions, marca Allow GitHub Actions to create and approve pull requests. Con eso, el workflow Sync profile:

    • cada lunes te abre un pull request con tus repositorios públicos nuevos, como proyectos en borrador;
    • cada tres meses te abre una issue para que traigas LinkedIn desde Studio. LinkedIn no deja que un workflow lea tu perfil sin ti.

    Mientras un proyecto tenga TODO, doctor bloquea el despliegue: aceptar el pull request sin completarlo no cambia tu web.

Recetas

Lo que harás a menudo, en orden, de principio a fin.

Actualizar tu perfil y tu web

./proofstack studio profiles/tu-nombre/profile.yaml    # edita, trae LinkedIn o GitHub, guarda; Ctrl+C al terminar
./proofstack doctor profiles/tu-nombre/profile.yaml    # 0 errores = se puede publicar
git add -A
git commit -m "Actualizo mi perfil"
git push                                               # la web y el CV se publican solos

Un CV para una oferta concreta

  1. Copia el texto de la oferta en un fichero, por ejemplo dist/oferta.txt.
  2. Genera el CV adaptado: 
    ./proofstack cv profiles/tu-nombre/profile.yaml --out dist/cv-oferta --job dist/oferta.txt
  3. Lee la salida de la terminal: Matches the posting es lo que ya tienes, y Posting asks, profile never says es lo que la oferta pide y tu perfil no menciona. Si de verdad lo tienes, añádelo al perfil y repite.
  4. Entrega dist/cv-oferta/cv.docx, o abre cv.html e imprímelo como PDF.

Un CV con tu teléfono, solo para enviarlo

El teléfono no se guarda en el perfil, porque el repositorio y la web son públicos. Se pasa al generar el CV:

./proofstack cv profiles/tu-nombre/profile.yaml --out dist/cv-privado --phone "600 11 22 33"

Para no escribirlo cada vez, guárdalo en la variable PROOFSTACK_PHONE de tu usuario (en PowerShell: [Environment]::SetEnvironmentVariable("PROOFSTACK_PHONE", "600 11 22 33", "User") y abre otra terminal). El CV publicado en la web nunca lo lleva. No compartas la carpeta dist/cv-privado en el repositorio: dist/ ya está en .gitignore.

Un CV centrado en un área

./proofstack cv profiles/tu-nombre/profile.yaml --out dist/cv-ia --focus ai -p 4

Áreas: backend, architecture, messaging, data, devops, ai, hardware, leadership, communication. -p es el número de proyectos.

Traer cambios de LinkedIn

Abre Studio y pulsa Traer de LinkedIn. Autoriza en la pestaña que se abre, revisa lo nuevo y guarda. La primera vez, ejecuta antes ./proofstack setup para dar de alta tu app de LinkedIn. Cada tres meses, el workflow Sync profile te abre una issue para recordártelo.

Desde la terminal, con la API:

./proofstack import linkedin-api `
  --merge-into profiles/tu-nombre/profile.yaml `
  --out profiles/tu-nombre/profile.linkedin.yaml --force

O con el ZIP que descargas de LinkedIn:

./proofstack import linkedin Basic_LinkedInDataExport.zip `
  --merge-into profiles/tu-nombre/profile.yaml `
  --out profiles/tu-nombre/profile.linkedin.yaml --force

Compara profile.linkedin.yaml con tu perfil (en VS Code: clic derecho → Compare Selected), copia lo que quieras conservar y borra el importado. Ese fichero no se sube a Git.

Añadir tus repos nuevos de GitHub

No tienes que hacer nada. Cada lunes, el workflow Sync profile busca tus repositorios públicos nuevos y te abre un pull request con ellos como proyectos en borrador. Complétalos (problema, solución, resultado) o bórralos, y acepta el pull request. Mientras queden TODO, la web no cambia.

Para que pueda abrir el pull request, activa una vez Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests.

Si no quieres esperar al lunes: botón Traer repos de GitHub en Studio, Actions → Sync profile → Run workflow en GitHub, o ./proofstack setup. Un repositorio que no quieras mostrar nunca va en github-ignore.txt, junto a tu perfil, una línea por repositorio.

Comprobar que la web publicada está bien

Pestaña Actions del repositorio: CI y Deploy portfolio en verde. Después abre tu web y pulsa Descargar CV.

Piezas opcionales

No hacen falta para la web ni el CV.

Borradores de posts, README o guiones con IA

Con Ollama en tu equipo (gratis y local):

ollama pull llama3.1
./proofstack generate linkedin-post profiles/tu-nombre/profile.yaml -s id-del-proyecto -m llama3.1 -o dist/post.md

Formatos: linkedin-post, readme, cv-bullets, video-script, evidence-draft, notebooklm-brief. Con Gemini: define $env:GEMINI_API_KEY y añade -p gemini. Es un borrador: reescríbelo con tu voz antes de publicar.

Tu perfil dentro de Kiro (MCP)

mvn -DskipTests package -pl proofstack-mcp-server -am

Copia docs/kiro-mcp.example.json a .kiro/settings/mcp.json y cambia las dos rutas: el jar (proofstack-mcp-server/target/proofstack-mcp-server-<versión>.jar) y tu perfil. Después pide a Kiro, por ejemplo: «Usa proofstack y escribe un post sobre mi proyecto agent-life». Solo lee el perfil, nunca lo modifica.

El asistente «pregúntale a mi portfolio»

Un servicio que responde preguntas sobre tu perfil citando las fuentes. Para probarlo en local:

mvn -DskipTests package -pl proofstack-ai-service -am
ollama pull nomic-embed-text
ollama pull llama3.1
$env:PROOFSTACK_PROFILE = "profiles/tu-nombre/profile.yaml"
java -jar (Resolve-Path proofstack-ai-service/target/proofstack-ai-service-*.jar)

# en otra terminal
Invoke-RestMethod http://localhost:8080/api/ask -Method Post -ContentType "application/json" -Body '{"question":"¿Qué proyectos de IA tiene?"}'

Para ponerlo en tu web necesitas alojarlo en un servidor con HTTPS (deploy/) y construir la web con --assistant-url https://tu-servidor.

Publicar una versión nueva (por ejemplo, 0.8.0)

  1. Apunta los cambios en CHANGELOG.md.
  2. Cambia la versión en todos los módulos (la CLI la lee del pom): 
    mvn versions:set "-DnewVersion=0.8.0" "-DgenerateBackupPoms=false" "-DprocessAllModules=true"
  3. Comprueba, sube y etiqueta: 
    mvn verify
git add -A
git commit -m "Release 0.8.0"
git tag -a v0.8.0 -m "Proofstack 0.8.0"
git push origin main v0.8.0
  4. El workflow Release CLI crea la Release con proofstack.jar y su SHA-256.

En PowerShell, deja las comillas de "-DnewVersion=0.8.0": sin ellas, PowerShell corta el valor en el punto.

Si algo falla

./proofstack no se reconoce
Estás en otra carpeta. Entra en la del repositorio con cd. En el CMD clásico de Windows escribe proofstack, sin ./.
File not found: profiles/…
La ruta es relativa a la carpeta en la que estás. Entra en la del repositorio.
Cambié el código y no se nota
El lanzador usa el último jar compilado. Recompila con mvn -DskipTests package -pl proofstack-cli -am.
Studio dice «Falta el token»
Abre la URL completa que muestra la terminal, con su #token=…. Cambia cada vez que arrancas Studio.
Studio dice que el fichero cambió en disco
Otro programa o un git pull lo modificó. Studio combina esos cambios con los tuyos y, si los dos cambiasteis el mismo campo, te pregunta cuál se queda. Revisa el resultado y pulsa Guardar. Si prefieres empezar de nuevo, Recargar desde el disco descarga antes tus cambios en profile.edited.json.
El despliegue falla en Ready to publish?
doctor encontró errores, o la variable PROOFSTACK_PROFILE falta o no es de repositorio. Ejecuta ./proofstack doctor en local: verás lo mismo que el log.
La web da 404
El primer despliegue aún no ha terminado, o Pages → Source no está en GitHub Actions.
Traer de LinkedIn dice que no está configurado
Ejecuta una vez ./proofstack setup profiles/tu-nombre y pega el Client ID y el Client Secret de tu app de LinkedIn. Cómo crear la app: docs/linkedin-api.md.
Sync profile falla al crear el pull request
Falta el permiso Settings → Actions → General → Allow GitHub Actions to create and approve pull requests. La rama proofstack/sync-github ya tiene los cambios: puedes abrir el pull request a mano.
Un repositorio que no quiero vuelve a salir
Añade su nombre, una línea por repositorio, a github-ignore.txt, junto a tu profile.yaml. setup lo hace solo con los que descartas.
LinkedIn responde 401
La app de LinkedIn debe usar la página Member Data Portability (Member-Only Default Company Page), y la API solo sirve a cuentas del EEE o Suiza. Fuera de ahí, usa el ZIP.
Maven muestra avisos WARNING: … sun.misc.Unsafe
Son del propio Maven con Java 25, no del proyecto. No afectan.
